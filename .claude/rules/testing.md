## Договоренности по тестированию

Данные договоренности описывают подход к тестированию в проекте, включая используемые фреймворки, подходы к написанию интеграционных тестов и шаблоны для именования тестов. Если unit-тесты не покрывают весь функционал, то необходимо писать интеграционные тесты, которые проверяют работу всей системы в целом. Если нет unit-тестов, то писать их не требуется если не было явного требования.

### Размещение
- Тест-проекта в репозитории сейчас нет. Когда он появится — это отдельный проект внутри `content/` соответствующего шаблона (`NET10.0/<Template>/content/`), чтобы тесты входили в состав генерируемого решения.

### Frameworks
- xUnit версии 3 и выше
- Moq (допустима замена на `NSubstitute`)
- AutoFixture

### Подходы
- Используй `WebApplicationFactory` для интеграционных тестов — запуск полноценного тестового сервера API.
- Unit-тесты — на `xUnit`; внешние зависимости изолируй мок-объектами.

### Шаблоны для именования
- `MethodName_Should_ExpectedBehavior_When_Condition` (например, `CreateUser_Should_ThrowException_When_EmailExists`) 
- `MethodName_ShouldNot_ExpectedBehavior_When_Condition` (например, `CreateUser_ShouldNot_ThrowException_When_EmailUnique`).
